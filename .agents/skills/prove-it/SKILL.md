# Prove It

Prove that the thing you just built or changed actually works.

Do not rely only on reading the code or saying it looks correct.

Test the real behavior.

## Verify

- Use the actual application or executable path when practical.
- Run relevant existing tests first when they help.
- Exercise the specific feature or change that was just made.
- Prefer the same path a real user would take.
- Capture clear evidence such as output, test results, screenshots, responses, or application state.
- Keep the verification focused on the work that changed.
- If something fails, say exactly what failed.
- Do not quietly work around failures just to produce a passing result.

## Core Rule

**Don't tell me it works. Prove it.**

Finish with a concise result:

**PASS** — what was verified and the evidence.

or

**FAIL** — what failed and what the evidence showed.
